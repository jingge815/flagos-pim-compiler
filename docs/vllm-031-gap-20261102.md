# vLLM 版本锁定与 0.31 适配差距（2026-11-02）

## 结论先说

PIM 后端只支持 **vLLM 0.14.x**，开发与回归都在 0.14.0 上跑。`PIMExecutor` 启动时
校验 `vllm.__version__`，不匹配直接失败并指向这份清单：

```text
PIM 后端只支持 vLLM 0.14.x，当前 0.31.0；装回 0.14.x，或按
docs/vllm-0.31-gap-20261102.md 完成适配
```

工作区 `.venv` 里的 0.31.0 只用于对照接口，没有跑通。

## 差距清单

下面按「改一个就跑不起来」到「可以先不动」排序。

| # | 接口 | 0.14（当前实现） | 0.31 | 影响 |
| --- | --- | --- | --- | --- |
| 1 | `WorkerBase.load_model` | `load_model()` | `load_model(*, load_dummy_weights: bool = False)` | 签名不兼容，`PIMWorker.load_model` 要接受关键字参数 |
| 2 | `WorkerBase.compile_or_warm_up_model` | 返回 `None` | 返回 `CompilationTimes(language_model, encoder)` | 返回值类型变了，需要返回零时长 |
| 3 | 采样拆分 | `execute_model` 直接返回 `ModelRunnerOutput` | 可返回 `None`，随后必须调用 `sample_tokens(grammar_output)` | 主机侧采样要挪到 `sample_tokens`，或在 `execute_model` 里保持同步返回（需实测是否允许） |
| 4 | `WorkerBase.initialize_cache` | 有，`initialize_cache(num_gpu_blocks, num_cpu_blocks)` | 已删除，只留 `initialize_from_config` | `PIMWorker.initialize_cache` 变成死代码，可删 |
| 5 | KV cache layout | 无 | 新增 `get_supported_kv_cache_layouts()` / `set_kv_cache_layout()` | 不实现则用默认布局；要确认默认值对 PIM 的 `[B, H, N, C]` 寻址无影响 |
| 6 | `KVCacheSpec` / `AttentionSpec` | `num_kv_heads`、`head_size`、`dtype`、`block_size` | 增加 `dcp_sharded`、`max_tp_shards`、`head_size_v`、`kv_quant_mode`、`page_size_padded`、`num_head_slots` 等；`FullAttentionSpec` 增加 `sliding_window` | 都有默认值，构造处预计不改 |
| 7 | `KVCacheConfig` | `num_blocks`、`kv_cache_tensors`、`kv_cache_groups` | 增加 `prefix_cache_retention_interval`、`kv_cache_layout`、`hisparse_host_num_blocks` | 只读 `num_blocks`，不受影响 |
| 8 | `NewRequestData` | 已有 `pooling_params`、`prompt_embeds`、`prefill_token_ids` | 增加 `prompt_is_token_ids`、`replay_start` | 我们只读 `block_ids`/`prompt_token_ids`/`num_computed_tokens`/`sampling_params`，不受影响 |
| 9 | `CachedRequestData` | `req_ids`、`resumed_req_ids`、`new_token_ids`、`all_token_ids`（dict）、`new_block_ids`、`num_computed_tokens`、`num_output_tokens` | 字段名与形状不变 | 无需改动 |
| 10 | `ModelRunnerOutput` | 我们只填 `req_ids` / `req_id_to_index` / `sampled_token_ids` / `logprobs` / `prompt_logprobs_dict` | 新增 `pooler_output`、`kv_connector_output`、`ec_connector_output`、`num_nans_in_logits`、`cudagraph_stats` 等（都有默认值） | 无需改动 |
| 11 | `SchedulerConfig.async_scheduling` | 无 | 新增，可开启异步调度 | 开启后 `execute_model` 的返回时序会变，先保持关闭 |
| 12 | `UniProcExecutor` | `vllm/v1/executor/uniproc_executor.py` | 路径与类名不变 | 不需要改，但要重跑端到端确认 RPC 行为 |

`WorkerWrapperBase` 在 0.31 里仍把 `initialize_from_config` 的列表参数拆成单个
`KVCacheConfig` 再转给 worker，所以 `PIMWorker` 的签名不用动。

## 升级顺序建议

1. 版本校验放宽到 0.31，先让 `PIMExecutor` 能起来。
2. 改 `load_model` 签名与 `compile_or_warm_up_model` 返回值，删 `initialize_cache`。
3. 处理 `execute_model` / `sample_tokens` 拆分：先试保持同步返回，跑不通再把采样挪过去。
4. 跑一遍现有 vLLM 用例（`tests/test_vllm_*.py`、`tests/test_prefix_cache.py`、
   `tests/test_preemption.py`、`tests/test_chunked_prefill.py`），确认块表、前缀缓存、
   抢占在 0.31 的调度输出上仍然成立。
5. 最后再评估是否开启 `async_scheduling` 与 KV cache layout 协商。

## 现有测试

`tests/test_vllm_compat.py`（2 例）：0.14.x 放行；0.31.0 报错，消息里同时有当前
版本与支持范围。
