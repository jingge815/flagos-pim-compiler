# KV 固定大小槽 + 间接寻址（2026-10-24）

## 目标

把 KV 缓存从「一个请求独占一整段 `max_seq` 大小的连续区域」改成**固定大小槽 + 运行期页表**：

- 一个请求按需占用多个槽，槽的物理位置由运行期分配；
- 内核不再用编译期算死的绝对地址，而是先读 DPU MRAM 里的页表，再按物理槽号寻址；
- 请求之间共享同一个物理槽池，池大小按并发上限预留。

这一步只做「固定槽 + 间接寻址」，**不做并发调度**：`execute_model` 仍逐请求串行执行，
但每个请求有独立的请求槽和页表，为下一步的连续批处理留好接口。

## 槽的粒度

一个物理槽 = 本 DPU 全部本地 KV 平面 × `slot_tokens` 个连续 token：

```
plane_bytes  = slot_tokens * head_dim * dtype_bytes
plane_stride = align_up(plane_bytes, align)
slot_bytes   = 2 * len(layers) * len(kv_heads) * plane_stride
```

槽内顺序仍是 `layer -> kv_head -> k/v`。`kv_off[(layer, head, k|v)]` 记的是
**物理槽 0 里的绝对地址**，因此旧代码里的 `kv_off` 语义只差一个槽号偏移。

## 地址公式

DPU `d`、请求槽 `r`、逻辑块 `b = pos // slot_tokens`、块内行 `t = pos % slot_tokens`：

```
物理槽   s = page_table[r][b]                  # int32，-1 表示未分配
平面地址 = kv_off[(layer, head, k|v)] + s * slot_bytes
行地址   = 平面地址 + t * head_dim * dtype_bytes
```

页表也放在 DPU MRAM，按请求槽分区：

```
blocks_per_request = ceil(max_seq / slot_tokens)
page_table_stride  = align_up(blocks_per_request * 4, align)
page_table_base    = kv_base
slots_base         = kv_base + num_request_slots * page_table_stride
pool_slots         = num_request_slots * blocks_per_request
kv_allocated_bytes = num_request_slots * page_table_stride
                     + pool_slots * slot_bytes
```

`kv_base` 仍是调用方给的起始地址，`KVRegionSpec.kv_allocated_bytes` 变成
「页表区 + 槽池」的整段大小；`kv_bytes()` 保留为未对齐的逻辑字节下界。

## 页表布局

每个请求槽一段固定长度的页表，项数 `blocks_per_request`，项类型 `int32`：

```
偏移  page_table_base + r * page_table_stride
长度  blocks_per_request * 4（不足 stride 的部分留空）
内容  逻辑块号 -> 物理槽号；未分配的块写 -1
```

`write_page_table(spec, hal, request_slot, block_table)` 负责补齐和越界检查。
内核读到 -1 时直接抛 `RuntimeError`，不读取垃圾数据。

## 分配与执行流程

```
step_request
  ├─ prefill: blocks.ensure(ceil(prompt_len / slot_tokens))
  ├─ decode : blocks.ensure(ceil((valid_len+1) / slot_tokens))
  ├─ 把 block_table 写成 int32 数组，写到每台 DPU 的页表区
  └─ execute_plan(..., request_slot=..., num_tokens=...)
                                    │
                                    ▼
                     sdpa_kernel 按 bound_request_slot 读页表
                       → 按物理槽写 K/V 行
                       → 按逻辑块 gather 历史
```

- `KVSlotPool`：全局物理槽池，`alloc()` 耗尽时抛 `RuntimeError`。
- `KVBlockTable`：一个请求的逻辑块表，`ensure(n)` 按需追加，`release()` 全部归还。
- `RequestTable(num_request_slots, kv_pool_slots)`：请求槽 + 物理槽池的统一入口。
- `RequestSlot.reset()` 先归还物理槽，再按新 prompt 重新 prefill（抢占重算用）。

`num_tokens` 限制本次真正写入的 token 数：vLLM 的静态 prefill 图会把短 prompt
右侧补齐，补齐位置不写 KV，也不参与历史长度计算（`hist_len = pos + num_tokens`）。

## 关键结构体

### `KVRegionSpec` 新增字段

| 字段 | 含义 |
| --- | --- |
| `slot_tokens` | 一个物理槽容纳的 token 数 |
| `blocks_per_request` | 每个请求槽的页表项数 |
| `pool_slots` | 物理槽总数（所有请求共享） |
| `page_table_base` | 页表区起始地址（= `kv_base`） |
| `page_table_stride` | 每个请求槽的页表占用字节数 |
| `slots_base` | 物理槽池起始地址 |
| `slot_bytes` | 单个物理槽的字节数 |

### `CompiledModel` 新增字段

| 字段 | 含义 |
| --- | --- |
| `num_request_slots` | 编译期预留的请求槽数（= 并发上限） |
| `kv_slot_tokens` | 编译时的槽粒度 |
| `kv_pool_slots` | 物理槽总数 |

### SDPA 命令 payload

```python
{
  "layer": int,
  "head_dim": int,
  "np_dtype": str,
  "slot_tokens": int,
  "heads": [{"head", "dpu", "row", "k_off", "v_off"}],
  "dpus": {dpu_id: {"pt_base", "pt_stride", "slots_base",
                    "slot_bytes", "blocks"}},
}
```

`k_off` / `v_off` 是槽 0 内的绝对地址，运行时由页表换成物理槽。

## 当前不足

- `execute_model` 仍串行逐请求执行，没有利用 `NumpyBackend` 的多 DPU 并发能力。
- vLLM 调度器给出的 `block_ids` 尚未消费；页表由 PIM 自己的分配器维护。
- 历史 gather 按逻辑块逐段 `read_local` 再拼接，块数多时调用次数线性增长。
- 不支持分块 prefill、前缀缓存和非贪心采样。
- 改并发数或 `slot_tokens` 必须重新编译。
