## 一、目标与范围

当前大模型经图编译、算子编译、GML 到单个 CEVA 仿真目标的流程已有运行产物。需要建立与甲方硬件对应的 GeneSim 配置和评估模型，并保持“大模型→图编译→算子编译→GeneSim”的完整链路可用。交付须同时证明配置实际生效、成本随工作量合理变化、产物确实来自编译链；只修改 YAML 或只生成成本 sidecar 不构成完成。

用户给出的规模为**单服务器 64 或 128 个 PIM 核，每核 local memory 标称 8 GB**，尚未限定只交付 64 核。实施可先以 64 核联调，保留并验证 128 核场景；单核场景用于校准。现有 `m32k_vpu500_dtcm64_8m_1024k_4e` 有 4 engine，厂商编译器负责核内并行；最终产品为 1 engine。4e 校准、1e 产品预测和多核扩展必须分别标明证据范围。

主要工作在 S；G/F 为真实分片、物理存储、计时工作量和产物接入提供必要配套。无需重构编译器或还原完整 GC 时间线，但若当前输入无法表达 W4A8 或真实计算规模，相应适配就是性能验收的前置依赖，不能一面排除它、一面宣称全链路性能对齐。C 的原始厂商目录只读。本轮仅修改需求与设计文档，不实施配置或模拟器代码，不运行长耗时 CEVA 全流程。

## 三、功能需求与验收

### R1（P0）独立纯 PIM 场景

CEVA 场景设置 `system.num_gpus=0`、`compute_config.gpu_compute=false`、`cpu_compute=false`、`pim_compute=true`，主机保留编排和必要 I/O。移除 GPU 链路与权重映射，禁止 `nodes/gpus` 等另一套资源入口绕过检查。使用 `./run.sh --config <CEVA场景>`，通用配置继续保留。关闭的是评估目标的 GPU 计算，不要求禁用构建机上用于 FlagGems/FlagTree 产物生成的 GPU。

验收实际 GPU 资源数和 GPU 执行算子数均为零，每个计算节点都有明确执行归属。CEVA runner 的 argmax、embedding LUT 等控制器工作须单列：纯 PIM 模型若不包含它们，只能与同边界的 NPM 子阶段比较；若报告 `full_execution`，须补充对应主机开销，不能无声删除。

### R2（P0）单核、64/128 核及 4e/1e 层级

首期采用整核等效模型：一个 GeneSim Node 表示服务器，一个 PIM device 表示其 CEVA 阵列，一个 ClusterPU 和其中唯一的 TensorPU 表示一个 NPM 核的调度资源。`clusters_per_device` 取 1、64、128，`tensors_per_cluster` 均为 1；真实 engine 数作为硬件画像元数据，4e/1e 使用不同成本配置。此映射是建模选择，不宣称已证实甲方互连拓扑。

逻辑 DPU 到核通过 `dpu_to_cluster` 显式一一映射，不允许取模或把多个 TP 分片无声挤到同一物理核。核内单个作业占用整核调度槽，成本已包含厂商 engine 并行；没有细分调度证据时不展开 engine 级资源。验收报告分别给出配置核数、实际创建核数、实际使用核数、物理 engine 数和模拟调度槽数，禁止把资源数等同于并行加速比。

### R3（P0）容量按字节统一

甲方给定的“8 GB”保留为硬件需求，字节口径未确认前不得写成已确认的 8 GiB。十进制 8 GB 为 8,000,000,000 B，对应现有字段 `7.450580596923828`；8 GiB 为 8,589,934,592 B，对应 `8.0`。两种口径可作显式假设对照，报告始终打印字节数和来源。

首期一核一个 TensorPU，已有容量校验即为整核上限，无需先开发跨 engine 共享容量去重。G 的 `HwBudget`、`PIMHardwareConfig` 与 S 使用同一字节预算，并声明系统预留。容量须包含实际物理权重、scale/bias、KV、激活及必要临时空间，区分模型常驻与并发请求占用；核内复用、生命周期和复制须有来源，不能把每个算子的工作集直接求和当作常驻量。

验收逐核容量恰好到限额通过、超出 1 B 失败，增加并发/KV 长度不能降低容量估计。`placed_mram_bytes` 是单算子放置工作集提示，不可替代整核分配台账。两字节完整 7B 模型不能在 8 GB 单核常驻；单核微基准不受此阻塞，但完整单核 W4A8 基线需先核对实际驻留/流式边界。

### R4（P0）整核计时、数据类型与工作量

CEVA 使用明确的内置轨迹后端，不因机器上是否安装 AttAcc/DRAMsim3 而改变计时。参数区分甲方规格、CEVA 测量、模型拟合和假设，记录单位、作用域、目标、精度和适用形状。`multipliers` 控制峰值估算，固定放置轨迹还须校准实际原语成本，不能只改峰值。

先修正工作量，再拟合成本。分块 `tt.dot` 路径与整算子 `pim.matmul`、量化、softmax 等相位路径分别核对 MAC 次数、元素/组数、循环、融合和 DMA；不同形状不能都以一条固定 MAC/SILU 成本代表。FP16 和 W4A8 混合数据类型按真实算子/张量计量，不能靠一个全局 `bytes_per_element` 或 `MAC` 参数同时解释所有路径。

当前模型逐条累加 DMA 与计算，不刻画算子内部重叠、缓存和 GC engine 调度。可先以实测拟合整核等效成本，但须记录这些适用边界；在独立验证集误差有系统性偏差时补充按阶段/形状的有效模型，不能用全模型倍率或扩大误差阈值掩盖。

### R5（P0）编译链实际接入

性能评估须保存同一模型及切分方案生成的 IR、放置 sidecar、成本 sidecar（使用时）、PIM MLIR、硬件预算、编译版本和哈希。明确配置 `model.ir_path`、`scheduler.compiler_placement_file`、`scheduler.cost_sidecar_file` 和 `trace.path`；实际分块优先于配置缺省值。

`require_compiler_pimir=true` 当前仅阻止“已声明路径却读不到”，未声明路径仍可走模板。正式评估须补全覆盖、内容哈希和类型/形状一致性检查；覆盖范围在 TP 展开、融合吸收和通信节点生成后定义。融合节点由所属主算子覆盖，纯视图和合成通信节点使用有证据的零计算/通信模型，数值归约不能被当成免费通信。其余计算节点缺少真实产物或出现未声明回退即失败。

现有 FP16 产物可用于全链路结构验证，不能冒充 W4A8 校准输入。若复用 CEVA 整算子 PIM MLIR，须建立与 GeneSim 算子、分片、prefill/decode 的对应关系及完整工作量提取；缺此适配时交付状态明确为“链路联调通过，W4A8 性能未验收”。

### R6（P0）通信、共享存储与多核扩展

根据甲方互连确认 HOST↔PIM、跨核链路的带宽、延迟、方向性、共享范围和路由；`bandwidth_gbps` 单位为 Gbit/s，不是 GB/s。同核数据访问通过本地计时覆盖，跨核数据边及 TP 集合通信单独计费，避免重复或漏计。

现有同设备跨簇路径使用一个设备级共享链路资源，不能靠配置链路带宽就模拟任意点对点网络；HOST 中转还含代码固定的 100 ns 开销。多核共享 DDR/控制器争用也不等于本地 LOADN/STOREN 周期。若甲方拓扑超出现有模型，增加所需端口/共享资源适配；没有资料时仅做注明假设的敏感性分析。

验收正字节跨核传输使用预期有限成本，给出字节数、服务时间、排队时间和共享资源键。纯视图、同核复用及无传输的零成本合法。64/128 核容量、通信量和繁忙度均须核对，不能把单核结果简单除以核数。

### R7（P0）同边界校准与结果分级

现有两组计数可作为分别校准的锚点：

| 包及证据 | prompt cycles | full_execution cycles | full 减去所列子阶段之和 |
| --- | ---: | ---: | ---: |
| C `baseline/results/performance_counters.txt` | 954872915 | 1150814443 | 458092 |
| C `runs/ours_e2e/run/performance_counters.txt` | 1028315650 | 1234494102 | 511074 |

C `runs/ours_e2e/results/verdict.txt` 记录 prompt 为 `hello how are you?`、10 次 decode、共 11 个输出 token，并存在与厂商 baseline 不同的 token 告警；其 PASS 不能解释成逐 token 一致。校准必须固定包、权重、量化、编译产物、输入及实际执行形状，不能将两包计数混合拟合。

C runner 在 prompt 执行前开始 `full_execution`，加载及初始化在此前，argmax/LUT 和部分控制器开销在该区间内。所列子阶段之和不等于 full，两者之差应单列残差，不应平摊到 MAC。计数器的控制器时钟与 NPM 时钟关系未确认前，保留原始计数器单位。

GeneSim prefill 请求的 `output_length` 包含首个 token，10 次 decode 对应 `output_length=11`；`--num_requests 10` 是 10 个请求，不是 10 步 decode。CEVA 的有效 prompt 长度、padding 后执行形状和初始 KV 须分别从输入/Registry 核对，不能用成本提取的 `--seq-len 128` 替代。

微基准分拟合集与独立验证集，逐点报告预测、观测、相对误差及绝对相对误差 median/p90/max，并覆盖计算、DMA、prefill、decode。只有匹配校准目标、数据类型、形状范围、执行边界且独立验证达标时，才称为已校准。64/128 核、1e 或未测通信均标注模型预测。时钟未知时算子周期仍可校准；混入 ns/Gbit/s 链路的系统周期依赖假设时钟，不能标为硬件周期。经确认的规格时钟同样可换算秒级结果，不限于实测来源。

## 四、交付与验收顺序

1. **结构基线**：1/64/128 核 × 4e/1e 画像，关闭 GPU，检查资源、显式映射、字节预算及后端。未知参数允许结构检查，但禁止进入正式性能运行。
2. **链路联调**：保留用户提供的模型解析、synthetic trace、TTIR/PIM MLIR 成本提取步骤；补充图切分、真实算子编译、放置导出和显式配置。小模型/少量请求只验接线；完整 Llama2-7B 和完整请求边界另验。
3. **单核校准**：先用已有计数和小规模代表算例，建立分形状、数据类型及 DMA 样本。完整包仅在有必要时复核，不将长耗时 CEVA 命令设为常规测试。
4. **多核预测**：为 64/128 核重新生成合法 TP/PP 计划及本地形状；Llama2-7B 有 32 层，不能直接要求 64/128 个非空纯 PP 段。明确实际使用核数，加入通信和并发对照。
5. **回归与报告**：实施后运行 S `./run.sh --test sim` 及 G/F 受影响测试；通用和 UPMEM 配置行为不变。报告保存解析后的配置、原始参数来源、所有输入摘要和版本。周期误差合格阈值由双方确认，已有工具的 ±20% 告警线不能直接作为 GeneSim 精度标准。

秒级指标满足时钟和边界条件后输出 TTFT、逐 token decode 时延、端到端时延、tokens/s，并说明是否含排队、主机开销、首次加载及完成请求数。不支持的真实张量 batch、多服务器、功耗面积和完整 GC 时间线不纳入本期。

## 五、待确认事项

- 64/128 核的交付优先级，以及“CEVA 节点”到 NPM 核、服务器的实际对应关系。
- 每核 8 GB 的准确字节数、可用容量及预留；已有 3983MB 目标的驻留与流式加载方式。
- 4e/1e 目标文件、各存储层级、时钟域、MAC 作用域；1e 的独立周期证据。
- 核间互连、主机接口和共享 DDR 的带宽、延迟、端口及争用范围。
- W4A8 真实产物映射与物理布局，分形状/分阶段测量来源，主校准包及数值一致性标准。
- 各层级误差阈值及多核代表测点。上述缺项不阻止文档和结构联调，但限制性能结论。

## 六、本轮校对记录

本次核对本地源码和现有运行产物，未重新执行 CEVA 或 GeneSim 全流程。删除旧稿无会话依据的“用户已澄清只做 64 核”“不再讨论 GB/GiB”等表述；修正 engine 与调度槽的混同、单算子工作集求和、全量 PIM MLIR 即保证正确计时、FP16 路径代表全部 FlagTree 能力等结论。补入相位计算量缺失、物理布局进入容量/通信的消费链、10 decode 对应 11 输出、主机残差、token 告警，以及 128 核和完整编译链的验收要求。具体实现选择与验证清单见配套设计。
