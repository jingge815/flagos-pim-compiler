# 基准回归门限（2026-11-02）

## 目的

G1/G3 的结论都以数字形式写在文档里（P=1/P=2 的墙钟、命令数、调度步数），
但这些数字没有任何东西守着：命令数涨回去、并行窗口退化、调度结构变了，
测试仍然全绿。G7 把两个基准的固定子集固化成 `tests/benchmarks.json`，
用 `scripts/check_benchmarks.py` 比对，越界即非零退出。

默认不跑（`verify.sh` 保持分钟级）；只有 `verify.sh --bench` 才跑，约 2 分钟。

## 做法

```text
scripts/verify.sh --bench
        │
        └─ scripts/check_benchmarks.py
              ├─ 读 tests/benchmarks.json（套件命令 + 基线 + 容差）
              ├─ 依次跑 bench_parallel.py / bench_vllm_scheduling.py --json
              └─ 逐指标比相对偏差，打印「基线 / 本次 / 偏差 / 容差 / 结论」
```

`--update` 用本次结果刷新指标值，容差与说明保持不变；`verify.sh` 永远不带它。

### 套件与容差

| 套件 | 固定子集 | 指标 | 容差 |
|---|---|---|---|
| `bench_parallel.py` | 4 DPU / 4 层 / hidden 1024 / 4 请求 × 8 步，P=1、2，重复 1 次 | `kernels`（内核调用数） | 0 |
| | | `wall_ms` | 50% |
| | | `util`（DPU 忙碌率） | 30% |
| `bench_vllm_scheduling.py` | `--only baseline,prefix` | `max_concurrency` | 0 |
| | | `decode_efficiency` | 20% |
| | | `wall_ms` | 50% |

计数类指标不随机器变化，容差为 0；墙钟与效率是耗时口径，容差按实测抖动放宽
（`decode_efficiency` 两次实测摆 3.8%，取 20% 挡「并发退化成串行」这种量级变化）。

## 基线（2026-11-02，本机）

| 套件 | 分组 | kernels | 墙钟 ms | util / 效率 | 最大并发 |
|---|---|---|---|---|---|
| bench_parallel | P=1 | 21 632 | 19 913.9 | 60.8% | — |
| bench_parallel | P=2 | 21 632 | 17 809.5 | 78.8% | — |
| bench_vllm_scheduling | baseline | — | 2 452.9 | 1.000 | 2 |
| bench_vllm_scheduling | prefix | — | 2 039.0 | 1.887 | 2 |

两组窗口的 `kernels` 相同，说明 P 只影响调度，不改变命令数——这正是 G1 的结论，
现在由门限钉住。

## 故意回归的验证

在基线里注入两处回归（模拟命令数变多、并行窗口被下调），再跑一次真实基准：

| 分组.指标 | 注入基线 | 本次实测 | 偏差 | 结论 |
|---|---|---|---|---|
| `2.kernels` | 20 000 | 21 632 | +1 632 | **超出** |
| `prefix.max_concurrency` | 1 | 2 | +1 | **超出** |

退出码 1，其余指标通过（墙钟偏差都在 ±3.3% 内）。恢复基线后重跑，12 项全部通过，
退出码 0。

## 更新规则（G7.2）

- 基线随每次改变性能特征的合并一起更新：`python scripts/check_benchmarks.py --update`。
- 提交信息必须写「为什么预期变化」（例：`kernels 21 632 → 15 000，RMSNorm 链融合`）。
- 换机器后即使代码没变也要重新生成：墙钟受机器影响，`--update` 前先在空载状态跑一次。
- 命令子集改动也算基线改动，同样要在提交信息里说明。

## 已实施的测试

| 判据 | 做法 | 结果 |
|---|---|---|
| 故意回归能失败并指出指标与偏差 | 注入上表两处偏差后运行 | 退出码 1，点名 `2.kernels`、`prefix.max_concurrency` |
| 正常状态通过 | 恢复基线后运行 | 12 项通过，退出码 0 |
| 默认 `verify.sh` 不跑基准 | `--bench` 才进该分支 | 默认路径不变 |

## 当前不足

- 基线绑定本机（墙钟、效率），跨机器比对没有意义；所以它只能按需跑，
  不能放进全量快测。
- 墙钟容差 50% 较宽：把 P 从 2 降到 1 只让墙钟涨约 12%，单靠墙钟抓不住；
  P 退化靠调度套件的 `max_concurrency`（2 → 1，容差 0）兜底。
- 基准用的是微型模型，不覆盖 7B；真实模型上的性能回归仍只能人工记录。
- `kernels` 只统计解码步的内核调用数，预填充路径的命令数不在门限内。
